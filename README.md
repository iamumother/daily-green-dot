# GitHub 每日绿点（已部署，2026-11-13）

仓库：iamumother/daily-green-dot（公开）。办法一（GitHub Actions）已上线：每天 UTC 14:23 自动往 logs/<年份>.md 追加一行并提交到 main，署名 iamumother 的 noreply 邮箱。

## 绿点计数规则（GitHub 官方文档，已核实）
- 提交的作者邮箱必须已绑定到你的 GitHub 账号。
- 仓库必须是独立仓库（不能是 fork），提交要进默认分支（main）或 gh-pages。
- 你必须是仓库所有者或协作者。
- 贡献图按 UTC 日期算，不是本地时区。
- 私有仓库的提交默认不显示，需要在主页设置里打开 “Private contributions” 才计入图中计数。

## 三个办法

### 办法一：GitHub Actions 自动提交（推荐）
专用仓库里放一个定时工作流（见 `.github/workflows/daily-green.yml`），每天自动往 logs 年文件追加一行并提交、推送。
- 优点：不依赖任何机器开机，GitHub 自己跑；每天的提交本身就是仓库活动。
- 注意：定时工作流是尽力执行，高峰期可能延迟甚至偶尔被丢弃；公开仓库若 60 天无活动会被自动停用定时工作流（本方案每天有提交，一般不会触发，但工作流一旦被停就不会自愈，需要偶尔检查或由周五汇总顺带核查）。
- 需要：GitHub 用户名、一个专用仓库（公开或私有）、提交邮箱与账号一致。

### 办法二：由小鲁每天定时跑
在小鲁这边建每日定时任务：拉取你的仓库，写当天日志并推送。
- 优点：内容可以是真实记录（当天任务摘要等），失败了会在周五汇总里报告。
- 缺点：依赖小鲁的运行环境；需要你通过安全方式提供仓库访问权（PAT 或部署密钥），密钥只进安全存储。

### 办法三：你自己的机器 / Simular Box 上跑脚本
本地 cron 每天提交推送。
- 缺点：机器要醒着；Simular Box 平时休眠，不适合做每日任务。可靠性最差，不推荐。

## 建议
选办法一；提交内容不要用空提交或纯时间戳，用每天一行的真实日志（日期 + 当天一句话记录），成本相同，绿点站得住。
